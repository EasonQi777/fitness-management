# 健身房会员办卡订单管理后台

连锁健身房会员办卡订单的中文管理后台：登录、订单列表（筛选 / 搜索 / 分页）、新建订单、续卡、撤单、CSV 导出。数据由项目内的内存模拟服务提供，无需启动后端。

需求来源：前端工程师的笔试题。

## 模拟数据说明

- 订单数据只保存在浏览器内存中。**刷新页面会把订单恢复为初始数据**，新建、续卡、撤单的结果随之丢失；登录信息保存在 localStorage，刷新后仍保留。
- 模拟服务仅用于演示前端设计与接口边界，不代表真实的服务端权限控制、持久化或财务账本。

## 接口契约

所有请求以 `/api` 为前缀，由 axios 自定义 adapter 交给内存模拟服务处理。除登录外均需 `Authorization: Bearer <token>`。写操作需 `Idempotency-Key` 请求头。

| 接口                          | 请求                                                                                                                                                                                                                                                                              | 成功响应                                                                                                                                                                                                                                       |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/login`            | `{ username, password }`                                                                                                                                                                                                                                                          | `{ token, username }`                                                                                                                                                                                                                          |
| `GET /orders`                 | 查询参数 `tab`（`all` / `in_progress` / `expired` / `completed` / `cancelled`，默认 `all`）、`orderNo`（去首尾空格后精确匹配）、`memberName`（去首尾空格后包含匹配，不区分大小写）、`page`（正整数，默认 1）、`pageSize`（10 / 20 / 50，默认 10）；条件为 AND，参数不合法返回 400 | `{ items, total, page, pageSize }`；按创建时间降序、同时间按 ID 升序；`total` 为分页前的匹配数；页码超出范围时 `items` 为空                                                                                                                    |
| `POST /orders`                | `{ memberName, phone, cardYears, remark }`，需 `Idempotency-Key`；校验规则与页面表单相同，字段错误以 `fieldErrors` 返回                                                                                                                                                           | 新建的订单：服务端生成 ID、订单号（`FM` + 上海日期 + 当日序号）与创建时间，金额 = 年限 × 1200，状态待审核，版本 1；忽略页面传入的金额、状态与编号                                                                                              |
| `POST /orders/renew`          | `{ orders: [{ id, version }], years }`，需 `Idempotency-Key`；`years` 为 1–10 整数，错误以 `fieldErrors.years` 返回；仅已到期订单可续                                                                                                                                             | `{ orders, unitPrice, totalPrice }`：累计年限增加、状态改待审核、版本加 1，金额与创建时间不变；`unitPrice` 为单笔续卡费用（≥ 5 年八折），`totalPrice` = 单笔 × 订单数                                                                          |
| `POST /orders/cancel`         | `{ orders: [{ id, version }] }`，需 `Idempotency-Key`；仅待制卡、待寄卡订单可撤                                                                                                                                                                                                   | `{ orders }`：状态改已取消、版本加 1，金额、年限与创建时间不变                                                                                                                                                                                 |
| `POST /orders/export-preview` | `{ scope: 'filtered', filters: { tab, orderNo, memberName } }`（与列表相同的筛选规则，不分页）或 `{ scope: 'selected', ids }`（勾选的订单 ID，可跨页、跨状态，不可为空或重复）；只读，不需要幂等键                                                                                | `{ items, excluded: [{ id, orderNo, reason }] }`：`items` 为已完成、已到期订单，按创建时间降序，只含 `id、orderNo、memberName、cardYears、amount、status、createdAt`；其他状态及不存在的 ID 列入 `excluded`（不存在时 `orderNo` 为 `null`）    |
| `GET /operation-logs`         | —                                                                                                                                                                                                                                                                                 | `{ items }`，按发生先后排列，每笔订单一条：`{ id, action（create / renew / cancel）, operator, operatedAt, orderId, orderNo, fromStatus, toStatus, renewYears?, renewFee? }`；只记录成功的写入，幂等重放不重复记录；仅供验证与调试，不建设页面 |

错误响应体统一为 `{ code, message, fieldErrors?, invalidOrders? }`，`invalidOrders` 每项为 `{ id, orderNo, reason }`（订单不存在时 `orderNo` 为 `null`）。定义见 `src/api/errors.js`。

| HTTP | `code`                 | 场景                                 | 页面处理（`parseApiError` 的 `kind`）                    |
| ---- | ---------------------- | ------------------------------------ | -------------------------------------------------------- |
| 400  | `VALIDATION_ERROR`     | 参数错误；表单错误附带 `fieldErrors` | 有 `fieldErrors` → `field`，显示在字段下；否则 `general` |
| 400  | `INVALID_ORDERS`       | 批量操作含不合格或不存在的订单       | `batch`，列出订单号与原因                                |
| 401  | `UNAUTHORIZED`         | 未登录或 token 无效                  | `unauthorized`，走统一退出流程                           |
| 404  | `NOT_FOUND`            | 接口不存在                           | `general`                                                |
| 409  | `VERSION_CONFLICT`     | 订单版本已变化，附带 `invalidOrders` | `batch`                                                  |
| 409  | `IDEMPOTENCY_CONFLICT` | 同一幂等键对应不同参数               | `general`                                                |
| 500  | `INTERNAL_ERROR`       | 模拟服务错误                         | `general`                                                |

请求被取消时为 `cancelled`，不提示；无响应的网络错误为 `general`。只有 `general` 由请求层统一提示（相同文案并发时只显示一条），其余由页面展示，避免重复提示。页面需要自行展示 `general` 错误时（如登录页、列表失败重试区域），请求配置传 `{ skipErrorToast: true }`。请求拦截器在每次请求时读取最新 token 注入 `Authorization`。

### 写操作规则

新建、续卡、撤单的处理顺序为：认证 → 幂等命中 → 参数与订单校验 → 一次性写入（实现见 `src/mock/writes.js`）。

- **幂等**：请求头 `Idempotency-Key` 必填。同一员工、同一接口、同一幂等键：请求体相同则直接返回首次成功的结果（不再执行，成功后的重试也不会误报版本冲突）；请求体不同返回 409 `IDEMPOTENCY_CONFLICT`。只保存成功结果，校验失败后可用同一个键修正重提。
- **订单引用**：续卡、撤单传 `orders: [{ id, version }]`，依次校验：空集合 / 格式错误 / 重复 ID（400 `VALIDATION_ERROR`）→ 订单不存在（`INVALID_ORDERS`）→ 版本已变化（409 `VERSION_CONFLICT`）→ 业务资格（`INVALID_ORDERS`）。每一步列出全部不合格订单及原因。
- **原子性**：全部校验通过后一次性写入，任一订单不合格则整批不修改。
- **操作日志**：与订单写入同时生效，失败的请求和幂等重放都不产生日志。
- **写入后**：页面重新查询当前条件；若当前页已超出总页数（如末页订单全部移出筛选），自动回到最后有效页（替换历史记录）。写入成功但列表刷新失败时，提示“操作已成功，列表刷新失败”，“重新加载列表”只重新查询，不会再次提交写入。

## 需求理解与业务决策

### 需求矛盾与处理

| #   | 需求原文                                                             | 问题                                         | 处理                                                                       |
| --- | -------------------------------------------------------------------- | -------------------------------------------- | -------------------------------------------------------------------------- |
| C1  | “订单列表默认按创建时间**升序**排列，保证最新创建的订单显示在最前面” | 升序会让最早的订单在最前，与“最新在最前”矛盾 | 以“最新在最前”为准，按创建时间**降序**；时间相同时按 ID 升序，保证排序稳定 |
| C2  | “任意账号密码均可登录成功”                                           | 是否包括空账号、空密码                       | 账号、密码必填，任意**非空**组合均可登录                                   |
| C3  | 续卡“费用 = 续卡年限 × 1200 元/年”                                   | 未说明续卡费用是否写入订单金额               | 订单金额保留原值，续卡费用记入操作日志（见 A6）                            |
| C4  | “接口偶尔也可能返回空值”                                             | 空金额的业务含义不明                         | 列表显示 `—`，与 `0.00` 区分；CSV 输出空单元格，不转为 0                   |

## Part 5：导出需求

业务方原始需求：

> 列表页帮我们加个导出功能吧，把订单数据导出来给财务对账用，金额格式弄得好看一点。对了，上次权限评审的时候说过，有些状态的订单是不能随便导出的，具体哪些你看着办。

### 澄清问题清单

1. 导出的是当前页、当前筛选的全部结果，还是勾选的记录？
2. 哪些订单状态允许导出？不同角色是否有不同权限？
3. 财务对账需要哪些字段？手机号和备注是否必要？
4. 订单金额代表首次购卡费用、累计收款，还是最近一次交易金额？
5. 金额是为了便于阅读，还是需要在表格软件中直接求和？
6. 空金额代表未知、未付款，还是零？
7. 批量操作混入不符合条件的订单时，应整批失败还是部分成功？
8. 续卡的八折优惠是否也适用于新建订单？
9. 手机号需要支持哪些国家或地区？
10. 创建时间应按哪个时区展示和导出？
11. 列表排序是否以“最新订单在最前”为准（原文“升序”与此矛盾）？
12. 正式提交的截止日期是什么？

### 导出实现假设

PDF 对导出只明确了四点：前端导出 CSV 文件即可、用于财务对账、“金额格式弄得好看一点”、“有些状态的订单是不能随便导出的，具体哪些你看着办”。下表“依据”列区分 PDF 明确要求与本项目的假设；标为**待业务确认**的条目在确认前不应视为既定规则，导出规则集中维护（`canExport`、`src/utils/ordersCsv.js`），便于确认后调整。

| #   | 假设                                                                                                                             | 依据                                                     |
| --- | -------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| E1  | 提供两个入口：“导出筛选结果”覆盖当前已提交查询条件的**全部分页**；“导出勾选记录”覆盖跨页勾选的订单，与当前页无关                 | 待业务确认（PDF 未说明导出范围，见澄清问题 1）           |
| E2  | 仅“已完成”“已到期”订单允许导出，其他状态被排除，并在导出前预览中列出被排除的订单号及原因                                         | 待业务确认（PDF 要求限制部分状态，具体状态由本项目假设） |
| E3  | 所有登录用户使用同一导出规则；生产环境应由后端权限系统执行，当前由模拟服务校验以体现边界                                         | 待业务确认（见澄清问题 2）                               |
| E4  | 导出字段：订单号、会员姓名、购卡年限、订单金额、状态、创建时间；**不导出手机号和备注**，避免对账文件携带非必要个人信息           | 待业务确认（PDF 只说明用途为财务对账）                   |
| E5  | 金额为订单当前记录的金额（不含续卡费用，见 A6），格式为千分位两位小数；空金额输出空单元格，`0` 输出 `0.00`                       | 格式参照 PDF 列表金额规则；金额口径待业务确认            |
| E6  | 千分位金额是文本，不保证所有表格软件都能直接识别为数字求和（见下方说明）                                                         | 待业务确认（对 “好看一点” 的理解）                       |
| E7  | 文件为 UTF-8 BOM 编码、CRLF 换行、固定中文表头；所有单元格加双引号并转义，以 `=`、`+`、`-`、`@` 或控制字符开头的文本做防公式处理 | CSV 为 PDF 明确要求；编码与转义为工程决策                |
| E8  | 先由模拟服务返回预览（可导出数量、排除数量及原因），用户确认后按该次预览数据生成文件；没有可导出记录时不生成空文件               | 工程决策                                                 |
| E9  | 文件名包含导出范围与上海时区的导出时间，如 `订单导出_筛选结果_20261015-154208.csv`                                               | 工程决策；时区待业务确认（见澄清问题 10）                |

### 导出文件说明

| 列       | 内容                                            | 示例                  |
| -------- | ----------------------------------------------- | --------------------- |
| 订单号   | 原样输出                                        | `FM20211102001`       |
| 会员姓名 | 原样输出；以公式字符开头时前加 `'`              | `阿依古丽·买买提`     |
| 购卡年限 | 累计年限，整数                                  | `2`                   |
| 订单金额 | 千分位两位小数；`0` 为 `0.00`；空金额为空单元格 | `2,400.00`            |
| 状态     | 中文状态名，只会是“已完成”或“已到期”            | `已到期`              |
| 创建时间 | 上海时间，精确到秒                              | `2021-11-02 09:05:41` |

关于千分位金额：每个单元格都以文本形式写入（带双引号），`12,000.00` 在 Excel、WPS 中通常按文本显示，**不能直接用 SUM 求和**，需要先“分列”或替换掉逗号转为数字。如果财务的主要用途是求和对账，更合适的做法是输出不带千分位的数字 `12000.00`，由表格软件设置显示格式——这需要业务确认后调整 `src/utils/ordersCsv.js` 中的金额列。页面列表中的空金额显示为 `—`，导出时为空单元格，避免对账时被当作字符或零。

导出相关的验证：CSV 编码与文本保护（`src/utils/ordersCsv.test.js`，使用独立的 RFC 4180 解析器读回）、导出预览接口的范围与资格（`src/mock/exportPreview.test.js`）、页面预览与下载交互（`src/components/ExportPreviewModal.test.jsx`、`src/pages/OrdersPage.test.jsx` 中“导出入口”“导出下载”），以及 Chromium 中真实下载并读取文件（`e2e/export.spec.js`）。
