# 健身房会员办卡订单管理后台

连锁健身房会员办卡订单的中文管理后台：登录、订单列表（筛选 / 搜索 / 分页）、新建订单、续卡、撤单、CSV 导出。数据由项目内的内存模拟服务提供，无需启动后端。

需求来源：前端工程师的笔试题。

## 目录约定

目录在首个文件出现时创建，不预建空目录。

| 目录          | 职责                                           |
| ------------- | ---------------------------------------------- |
| `src/pages`   | 路由页面（登录、订单列表、新建订单、404）      |
| `src/layouts` | 后台布局（菜单、顶栏、面包屑）                 |
| `src/api`     | axios 实例、拦截器与接口函数                   |
| `src/mock`    | 内存模拟服务与 axios adapter，页面不得直接引用 |
| `src/store`   | zustand 认证状态                               |
| `src/hooks`   | 页面复用的 hook（如 `useOrders`）              |
| `src/domain`  | 前端与 mock 共用的业务规则（状态、价格、验证） |
| `src/utils`   | 与业务无关的工具（格式化、下载）               |
| `src/test`    | 测试环境配置                                   |
| `e2e`         | Playwright 端到端测试                          |

样式：Ant Design 负责组件，Tailwind 负责页面排版与间距。未引入 Tailwind Preflight；antd 样式通过 `StyleProvider layer` 放入 `antd` 层，Tailwind 工具类可覆盖组件默认样式。

## 模拟数据说明

- 订单数据只保存在浏览器内存中。**刷新页面会把订单恢复为初始数据**，新建、续卡、撤单的结果随之丢失；登录信息保存在 localStorage，刷新后仍保留。
- 模拟服务仅用于演示前端设计与接口边界，不代表真实的服务端权限控制、持久化或财务账本。

## 需求理解与业务决策

### 需求矛盾与处理

| #   | 需求原文                                                             | 问题                                         | 处理                                                                       |
| --- | -------------------------------------------------------------------- | -------------------------------------------- | -------------------------------------------------------------------------- |
| C1  | “订单列表默认按创建时间**升序**排列，保证最新创建的订单显示在最前面” | 升序会让最早的订单在最前，与“最新在最前”矛盾 | 以“最新在最前”为准，按创建时间**降序**；时间相同时按 ID 升序，保证排序稳定 |
| C2  | “任意账号密码均可登录成功”                                           | 是否包括空账号、空密码                       | 账号、密码必填，任意**非空**组合均可登录                                   |
| C3  | 续卡“费用 = 续卡年限 × 1200 元/年”                                   | 未说明续卡费用是否写入订单金额               | 订单金额保留原值，续卡费用记入操作日志（见 A6）                            |
| C4  | “接口偶尔也可能返回空值”                                             | 空金额的业务含义不明                         | 列表显示 `—`，与 `0.00` 区分；CSV 输出空单元格，不转为 0                   |

### 业务默认决策

“待业务确认”表示该项是为完成实现做出的假设，正式上线前需要业务方确认。

| #   | 决策                                                                                                       | 性质                     |
| --- | ---------------------------------------------------------------------------------------------------------- | ------------------------ |
| A1  | 列表按创建时间降序，时间相同时按 ID 升序                                                                   | 默认决策（C1）           |
| A2  | 新建费用 = 年限 × 1200 元，不打折                                                                          | 需求明确                 |
| A3  | 续卡费用 = 本次续卡年限 × 1200 元；本次续卡 ≥ 5 年时按八折计算，折扣按**本次**续卡年限判断，与累计年限无关 | 需求明确 + 默认决策      |
| A4  | 批量续卡对每笔订单使用相同年限，应付总额 = 单笔费用 × 订单数                                               | 默认决策                 |
| A5  | 单次购卡、续卡年限为 1–10 的整数；累计购卡年限允许超过 10                                                  | 默认决策                 |
| A6  | 续卡成功后累计年限增加、状态改为待审核；**订单金额保留原值**，续卡费用写入操作日志                         | 待业务确认（金额口径）   |
| A7  | 撤单后状态改为已取消，保留原金额与年限                                                                     | 默认决策                 |
| A8  | 金额以整数“元”存储，允许为空；展示为千分位两位小数，如 `12,000.00`；`0` 显示 `0.00`，空值显示 `—`          | 需求明确 + 默认决策      |
| A9  | 会员姓名去除首尾空格后为 2–30 个字符（按 Unicode 字符计数）；备注选填，最多 200 字                         | 默认决策                 |
| A10 | 手机号仅支持中国大陆 11 位号码，规则 `^1[3-9]\d{9}$`，前端与模拟服务一致                                   | 待业务确认（手机号地区） |
| A11 | 创建时间以带时区的 ISO 字符串保存，统一按 `Asia/Shanghai` 显示为 `YYYY-MM-DD HH:mm:ss`                     | 待业务确认（时区）       |
| A12 | 批量续卡、批量撤单先整批校验，任一订单不合格则整批失败并列出订单号与原因，不做部分成功                     | 默认决策                 |
| A13 | 写操作使用订单版本号防止基于过期数据操作；使用幂等键防止重复提交造成重复写入                               | 默认决策                 |
| A14 | 仅“已到期”可续卡；仅“待制卡”“待寄卡”可撤单；未知状态不允许任何操作                                         | 需求明确 + 默认决策      |
| A15 | 不实现审核、制卡、寄卡、自动到期、支付和订单编辑；这些状态由模拟数据覆盖                                   | 默认决策                 |
| A16 | 模拟写入只保存在内存，刷新恢复初始订单；登录信息保留                                                       | 需求允许                 |

## Part 5：导出需求

业务方原始需求：

> 列表页帮我们加个导出功能吧，把订单数据导出来给财务对账用，金额格式弄得好看一点。对了，上次权限评审的时候说过，有些状态的订单是不能随便导出的，具体哪些你看着办。

### 澄清问题清单

1. 导出的是当前页、当前筛选的全部结果，还是勾选的记录？
2. 哪些订单状态允许导出？不同角色是否有不同权限？
3. 财务对账需要哪些字段？手机号和备注是否必要？
4. 订单金额代表首次购卡费用、累计收款，还是最近一次交易金额？
5. 金额是为了便于阅读，还是需要在表格软件中直接求和？
6. 空金额代表未知、未付款，还是零？
7. 批量操作混入不符合条件的订单时，应整批失败还是部分成功？
8. 续卡的八折优惠是否也适用于新建订单？
9. 手机号需要支持哪些国家或地区？
10. 创建时间应按哪个时区展示和导出？
11. 列表排序是否以“最新订单在最前”为准（原文“升序”与此矛盾）？
12. 正式提交的截止日期是什么？

### 导出实现假设

以下为第一版假设，均**待业务确认**；导出规则集中维护，便于确认后调整。

| #   | 假设                                                                                                                             |
| --- | -------------------------------------------------------------------------------------------------------------------------------- |
| E1  | 提供两个入口：“导出筛选结果”覆盖当前已提交查询条件的**全部分页**；“导出勾选记录”覆盖跨页勾选的订单，与当前页无关                 |
| E2  | 仅“已完成”“已到期”订单允许导出，其他状态被排除，并在导出前预览中列出被排除的订单号及原因                                         |
| E3  | 所有登录用户使用同一导出规则；生产环境应由后端权限系统执行，当前由模拟服务校验以体现边界                                         |
| E4  | 导出字段：订单号、会员姓名、购卡年限、订单金额、状态、创建时间；**不导出手机号和备注**，避免对账文件携带非必要个人信息           |
| E5  | 金额为订单当前记录的金额（不含续卡费用，见 A6），格式为千分位两位小数；空金额输出空单元格，`0` 输出 `0.00`                       |
| E6  | 千分位金额是文本，不保证所有表格软件都能直接识别为数字求和——这是需要财务确认的格式假设                                           |
| E7  | 文件为 UTF-8 BOM 编码、CRLF 换行、固定中文表头；所有单元格加双引号并转义，以 `=`、`+`、`-`、`@` 或控制字符开头的文本做防公式处理 |
| E8  | 先由模拟服务返回预览（可导出数量、排除数量及原因），用户确认后按该次预览数据生成文件；没有可导出记录时不生成空文件               |
| E9  | 文件名包含导出范围与上海时区的导出时间                                                                                           |
